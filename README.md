# LayerTalk

発表中のスライドの最前面に、観客からのリアルタイムコメントとスタンプを
「背景透過・クリックスルー」で重ねて表示します。

```
apps/audience-web/     観客用 Web (Next.js 16 / スマホから開く)
apps/presenter-app/    発表者用 macOS アプリ (Tauri v2 + React)
packages/shared/       型・Supabase クライアント・Realtime フック・デザイントークン
supabase/migrations/   スキーマ（MCP で適用済みのミラー）
docs/design-system.md  デザインの正
```

## セットアップ

```bash
# Rust（presenter-app のビルドに必須）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y

npm install
```

環境変数は各アプリの `.env.local` に入れます（`*.local` は gitignore 済み）。
`.env.example` を参考にコピーしてください。キーは publishable なので露出前提です。

観客用 Web をデプロイしたら、発表者用アプリの `VITE_AUDIENCE_BASE_URL` にその URL を設定します。
未設定だと `http://localhost:3000` になり、**参加 QR を観客のスマホから開けません**。

## 起動

```bash
npm run dev:web        # 観客用 → http://localhost:3000
npm run dev:presenter  # 発表者用（オーバーレイ窓 + コントロール窓）
```

1. `dev:presenter` を起動 → コントロール窓で **新しいルームを作成**
2. **表示モニター**を選ぶ（選ぶとその画面に確認用の枠が数秒出ます）
3. 表示スタイルや速さを調整（「スタンプをテスト送信」でその場で確認できます）
4. **「プレゼンを開始」**を押す → 選んだモニターにオーバーレイが出ます
5. 6桁コード（または「観客用URLをコピー」）を観客に共有
6. 観客は `http://localhost:3000/r/<コード>` を開いてコメント・スタンプを送る
   （コメントは **Enter で送信・Shift+Enter で改行**。入力欄の下にも書いてあります）

観客はルート `/` から6桁コードを入力して入室することもできます。

> **開始を押すまでオーバーレイは一切表示されません。**
> また、**開始より前に投稿されたコメントは流れません**（新規のみ）。
> リハーサルや前の発表のコメントで画面が埋まらないようにするためです。
> 終了してもルームは残るので、同じコードですぐ再開できます。
> 別のルームに移りたいときは「ルームを切り替える」を押すと作成／参加のカードに戻ります。
> 前のルームは消えないので、コード（または「直前のルーム … に戻る」）でいつでも再開できます。

## 発表者用アプリの操作

| 操作 | 方法 |
|---|---|
| コントロール窓を出す | `⇧⌘L` またはメニューバーのトレイアイコン |
| プレゼンの開始 / 終了 | コントロール窓の主ボタン（終了はトレイからも） |
| ルームを切り替える | コントロール窓「ルーム」→「ルームを切り替える」（発表中は不可） |
| 参加 QR をスライドに出す | コントロール窓「ルーム」→「スライドに参加QRを表示」（左下に出ます） |
| 表示モニターを選ぶ | コントロール窓「表示モニター」 |
| 画面サイズに合わせ直す | コントロール窓のボタン（外部ディスプレイ接続後に押す） |
| 表示スタイル切替 | コントロール窓「横流れ / フキダシ」 |
| 演出の速さを詰める | コントロール窓のスライダー ＋「スタンプをテスト送信」ボタン |
| アプリの終了 | トレイ →「LayerTalk を終了」 |

**クリックスルーは常時 ON の固定仕様**です。オーバーレイはマウス操作を一切受け取らず、
クリックもスクロールもそのまま背面のスライドに届きます。切り替える手段は用意していません
（発表中に気づかないまま背面が操作できなくなる事故を作らないため）。

ルーム未接続のあいだ、オーバーレイはダミーのコメントとスタンプを流します
（透過とクリックスルーの目視確認用）。

Dock アイコンは出ません（`ActivationPolicy::Accessory`）。⌘-Tab にも現れませんが、
`⇧⌘L` でコントロール窓を最前面に呼び出せます（トレイアイコンからも復帰できます）。

## 動作確認

```bash
npm run typecheck        # 両アプリの型検査
npm run build:web        # 観客用の本番ビルド
npm run smoke:realtime   # Realtime 3経路（INSERT / UPDATE / Broadcast）の疎通
```

オーバーレイの透過とクリックスルーは自動テストできないので、実機で確認してください:

1. 「プレゼンを開始」を押す前は、どの画面にも何も出ていないこと
2. Keynote / PowerPoint をフルスクリーンでスライドショー開始
   （ブラウザの全画面プレゼン — Canva / Notion / Google スライド — も別 Space になるので、
   罠 #9 の載せ替えが効いているか確認するならこちらも一度は通すこと）
3. 開始を押すと、選んだモニターにコメントとスタンプがその上に見えるか
4. スライド上のクリック・スクロールが背面アプリに届くか
5. 終了を押すと消え、ルームコードは残っていて再開できるか

演出の速さだけを詰めたいときは、スライドショーを開くまでもありません。
トレイからコントロール窓を開き、スライダーを動かして「スタンプをテスト送信」を押せば、
開始前でも確認のあいだだけオーバーレイが出ます。

## 設計上の要点

**オーバーレイが発表アプリより前に出る仕組み**
Tauri の `alwaysOnTop`（NSFloatingWindowLevel）だけではスライドショーに隠れます。
`src-tauri/src/lib.rs` で NSWindow のレベルを `kCGScreenSaverWindowLevel` (1000) に上げ、
`collectionBehavior` に `CanJoinAllSpaces | FullScreenAuxiliary` を立てています。
`app.macOSPrivateApi` と cargo feature `macos-private-api` は透過に必須です
（そのぶん Mac App Store 配布はできません）。

**いいねの改ざん防止**
`comments` の UPDATE を anon に開けると `content` まで書き換えられるため、ポリシーは作らず
`security definer` の `toggle_comment_like()` だけを公開しています。
`comment_likes` は端末ごとの匿名 `client_id` で重複を防ぎ、同時にトグル（取り消し）も成立させます。

**Realtime の取りこぼし対策**
`SUBSCRIBED` が返っても、レプリケーションのフィルタが実際に効き始めるまで 1〜2 秒のズレがあります
（`npm run smoke:realtime` で再現可能）。`useComments` は購読確立の直後と 2.5 秒後の 2 回取得し直し、
その隙間に入ったコメントを回収します。再接続時も同じ経路を通ります。

**`onInsert` の発火判定を setState の中でやらない**
`useComments` は「演出を流したか」を `seenIdsRef`（ref の Set）で持っています。
React の state 更新関数は呼び出し時点では実行されないため、その中でフラグを立てて
直後に読むと**必ず初期値のまま**です。実際にこれで `onInsert` が一度も呼ばれず、
「スタンプは流れるのにコメントだけ流れない」バグになりました。
この Set は同時に「開始前の投稿を流さない」判定にも使っています。

**スタンプを DB に置かない理由**
永続化する価値が無く、投稿のたびに WAL を汚すため。Broadcast でクライアント間に直接流します。
連打は 100ms 単位で絵文字ごとに集約してから送り、Realtime のレート上限に当てないようにしています。

## 既知の制約

- **匿名アプリなので、いいねの水増しは原理的に防げません。** `client_id` は端末が自由に作れるため、
  本気で対策するなら認証が要ります。現状は「うっかり連打」を防ぐところまでです。
- ルーム作成は anon に開いています（発表者を認証で縛っていない）。
- Supabase の advisor は5件の指摘を出しますが、いずれも上記の設計を選んだ結果で、意図どおりです。
- `@supabase/supabase-js` は Node 22 以降を推奨しています。ブラウザ実行には影響しませんが、
  Node からこのライブラリを使う場合（`smoke:realtime` など）は WebSocket の注入が必要です。
- 複数モニタは未対応（プライマリモニタのみ）。

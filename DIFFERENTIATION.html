LayerTalk / 競合と差別化

「なんでもいける」は正しい。
ただし、それだけでは差別化にならない。

2026-08-11 社内メモ 競合情報は公開情報ベース・要再確認

Canva・PowerPoint・Google Slides に縛られないのは LayerTalk の強みで間違いない。 ただしそれは「画面に重ねる」というアプローチ全体の強みで、 同じアプローチの先行プロダクトがすでにある（Comment Screen）。

だから訴えるべきは「どのツールでも使える」ではなく、 重ねたあとに何が起きるか——発表者が事故らないこと、 流れる声と残る質問が分かれていること、データが自分の手元にあること。

01 — 市場の地図

競合は2種類いる。戦う相手が違う。

観客参加ツールは、スライドの中に住むものと画面の上に住むものに割れる。 ここを混ぜて語ると差別化がぼやける。

埋め込み型（Slido / Mentimeter / Poll Everywhere）は PowerPoint・Google Slides のアドインとして、あるいは自社エディタとして動く。 投票やクイズ、モデレーション付き Q&A の運用は厚い。かわりに スライド以外の画面には原理的に出られない—— ライブコーディング中のエディタにも、デモ中のブラウザにも重ねられない。

オーバーレイ型（Comment Screen / LayerTalk）は画面そのものに重ねる。 だから何を映していても効く。ここが指摘のとおり効く一方で、 この土俵にはすでに先行者がいる。Comment Screen は ニコニコ動画式に画面へコメントを流す発想で、観客はアプリを入れずスマホから投稿でき、 QR での参加もできる。「ツールを選ばない」「アプリ不要」だけでは並ぶだけになる。

02 — 勝ち筋

重ねたあとに何が起きるかで差がつく

A — 事故らない

発表者が失敗しようがない設計

クリックスルーは常時 ON で切り替え UI すら持たない（気づかず背面を操作不能にする事故が起きない）。 開始を押すまで何も出ず、開始より前の投稿は流さない（リハーサルの残骸が本番に出ない）。 Dock にも ⌘-Tab にも現れず、⇧⌘L とメニューバーだけで戻れる。 表示先モニターは選んだ画面に確認枠を出して選ばせる。

B — 分ける

流れて消える声と、残って効く質問

コメントとスタンプは流れて消える。質問は同じように流れたうえで、 右端のパネルに新着順で残り、折りたたむと未読数だけが出る。 いいねの多い質問が上に来る。 オーバーレイ型に Q&A の運用を持ち込んでいるのは、この土俵では新しい。

C — 手元に置く

データも運用も自分の側

発表者アカウントなし、観客はアプリ不要で6桁コードか QR。 バックエンドは自分の Supabase プロジェクトなので、 社内の発表内容が他社の SaaS に残らない。参加人数での課金もない。 社内利用のセキュリティ審査に対して強い立ち位置。

03 — 裏付け

言えることは、実装で担保されている

  • フルスクリーンのスライドショーより前に出る。 alwaysOnTop（NSFloatingWindowLevel = 3）では Keynote / PowerPoint に負けるので、NSWindow を直接 1000 まで上げ、CanJoinAllSpaces | Stationary | IgnoresCycle | FullScreenAuxiliary を立てている。ここが競合との比較で一番効く一点。
  • クリックスルーは固定仕様。 オーバーレイはマウスを一切受け取らない。操作が要る質問パネルだけを別ウィンドウに切り出して、右端の範囲内でだけ受け取る。
  • スタンプは DB に書かない。 Broadcast のみ、連打は 100ms 単位で集約してから送る。会場全員が連打しても DB が詰まらない。
  • 取りこぼしを前提に組んである。 Realtime は購読確立からフィルタが効くまでズレるので、購読直後と 2.5 秒後の二度取り直して回収する。
  • 会場の Wi-Fi を疑っている。 数MBの日本語 Web フォントは読み込まない。観客側はダーク基調（暗い会場でスマホを見る前提）。
04 — 提案

差別化を厚くするなら、この順で

01

ライブコーディング・デモに寄せて名乗る コスト小

埋め込み型が原理的に入れない領域がここ。スライドではなくエディタ・ターミナル・ブラウザ・Figma を映している時間こそ、 観客の反応が欲しい。「勉強会・ハンズオン・ライブコーディングで使える唯一の観客参加ツール」と名乗るだけで立ち位置が変わる。 機能としては「コメントを画面下 25% に寄せる」オプションがあれば、コードを隠さずに済む。

02

発表の記録を書き出す コスト小

コメントには時刻があり、開始時刻はアプリが持っている。「開始から何分何秒に、どの声が来たか」を Markdown / CSV に出せる。どこで沸いてどこで質問が出たかは、次の発表を直す材料そのもの。 競合はレポートを上位プランに置いていることが多く、こちらは無料で出せる。

03

モデレーション（NGワード・個別非表示・数秒ディレイ） コスト中

社外イベントや社内の大きな会で採用されるかは、ほぼここで決まる。いまは何も無い＝提案時の一番の穴。 全部は要らない。「いま流れているものを1クリックで止める」のが最優先で、次に NG ワード。

04

オンライン会議での挙動を検証して明記する コスト小

画面に重ねる方式は、Zoom / Meet で「画面全体」を共有していれば相手にも映り、「ウィンドウ」共有だと映らない。 この一行を書けるかどうかでオンライン用途の信頼が変わる。実機で確認してドキュメントに残す。

05

Windows 対応 コスト大

企業の発表現場の多数派。Tauri なので土台は同じだが、最前面化とクリックスルーは OS ごとに別実装になる。 差別化ではなく市場の広さの問題なので、上の4つを終えてから。

05 — 穴

正直に埋めておくべきところ

  • macOS 専用。 しかもコード署名・公証をしていないので、配布すると Gatekeeper に止められる。
  • 荒らしに無防備。 認証が無いので、いいねの水増しも不適切投稿も止められない（提案03がそのまま対策）。
  • 観客用 Web が未デプロイ。 QR も URL 共有も、公開ホストに出すまで本番では使えない。
  • 投票・クイズは無い。 ただしこれは Mentimeter / Poll Everywhere の土俵で、追うと消耗戦になる。「反応が流れる」体験に絞るのが正解だと思う。
06 — 言い方

そのまま使えるピッチ

スライドを選ばない。画面に重ねるから、Keynote でも VS Code でも、デモ中のブラウザでも観客の声が流れる。

観客はアプリを入れず、QR か6桁コードだけで参加。コメントとスタンプは流れて消え、質問だけが画面の右端に残る。 発表者側はクリックスルー固定なので、スライド操作を一切邪魔しない。開始を押すまでは何も映らないので、リハーサルの声が本番に流れることもない。 バックエンドは自分の Supabase なので、発表の内容も参加者の声も社外に出ない。
